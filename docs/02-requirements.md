# 1차 MVP 기능 요구사항

> 문서 상태: 구현을 시작하기 위한 초기 요구사항 기준선이다. 승인된 업무 규칙은 보존하되 URI, 문자열 길이, 응답 형태와 내부 구현은 변경될 수 있다.

결정 상태는 [결정 기록](./01-decisions.md)을, HTTP 계약과 오류 코드는 [API 명세](./06-api-spec.md)를 따른다.

## 대상 사용자와 권한

| 대상 | 주요 행동 | 권한 기준 |
|---|---|---|
| 비회원 | 구장·코트 조회, 매치 목록·상세 조회, 회원가입·로그인 | 공개 API |
| 로그인 회원 | 프로필 수정, 매치 개설, 참가·취소, 내 매치 조회 | 인증 필요 |
| 특정 매치 주최자 | 매치 수정, 모집 마감·재개, 매치 취소, 참가자 목록 조회 | 인증 + 주최자 관계 확인 |
| 특정 매치 참가자 | 자신의 참가 취소, 조건 충족 시 재참가 | 인증 + 참가 관계 확인 |

주최자와 참가자는 전역 Role이 아니라 매치별 관계이며 서로 독립적이다. 주최자도 참가를 선택하면 MatchParticipation을 가지며 다른 참가자와 동일하게 정원에 포함된다.

## 핵심 사용자 흐름

### 참가자 흐름

1. 구장·코트와 참가 가능한 매치를 조회한다.
2. 매치 상세에서 일정, 장소, 모집 상태와 남은 자리를 확인한다.
3. 로그인 후 참가를 요청한다.
4. 서버가 매치 상태, 모집 상태, 시작 시각, 기존 참가 관계와 남은 자리를 검증한다.
5. 성공하면 참가 관계가 `CONFIRMED`가 된다. 실패하면 참가 상태와 정원은 변하지 않는다.
6. 내 참가 매치에서 결과를 확인한다.
7. 시작 전에 참가를 취소하면 `CANCELLED_BY_MEMBER`로 전이한다.
8. 이후 조건이 맞으면 기존 관계를 `CONFIRMED`로 재참가시킨다.

### 주최자 흐름

1. 로그인 후 구장과 코트를 조회한다.
2. 코트, 제목, 안내, 권장 실력, 일정, 정원과 주최자 참가 여부를 입력해 매치를 개설한다.
3. 매치는 `SCHEDULED`·`OPEN`으로 시작한다.
4. 주최자가 참가를 선택하면 주최자의 `CONFIRMED` 참가 관계도 같은 유스케이스에서 생성한다.
5. 주최자는 참가자 목록을 확인하고 시작 전까지 허용된 정보를 수정하거나 모집을 마감·재개한다.
6. 시작 전에 매치를 취소하면 Match와 활성 참가 상태가 함께 취소된다.

## 권한 요구사항

| 기능 | 공개 | 로그인 회원 | 해당 주최자만 |
|---|:---:|:---:|:---:|
| 회원가입·로그인, 구장·코트, 매치 목록·상세 | O | O | - |
| 로그아웃·현재 회원·프로필 수정 | - | O | - |
| 매치 개설 | - | O | - |
| 매치 참가·취소·내 참가 매치 | - | O | - |
| 내가 주최한 매치 | - | O | - |
| 매치 수정·모집 마감·재개·취소 | - | - | O |
| 해당 매치 참가자 목록 | - | - | O |

미인증 보호 요청은 401, 인증됐지만 주최자 관계가 없는 요청은 403, 리소스 없음은 404, 현재 상태와 명령 충돌은 409로 구분한다.

## 기능 요구사항

### 회원·인증

| ID | 목적 | 선행 조건 | 성공 결과 | 대표 실패 조건 | API 후보 |
|---|---|---|---|---|---|
| `MEM-001` | 비회원이 계정 생성 | email·password·nickname 유효 | 회원 생성, 자동 로그인하지 않음 초기안 | 검증 실패, email 중복, nickname 중복 정책 충돌 | `POST /api/members` |
| `MEM-002` | 회원이 최소 프로필 수정 | 로그인, 허용 필드 유효 | 닉네임 등 허용 필드 갱신 | 미인증, 검증 실패, nickname 중복 정책 충돌 | `PATCH /api/members/me/profile` |
| `AUTH-001` | 회원 로그인 | 유효한 자격 증명 | 인증 세션 수립 | 자격 증명 불일치 | `POST /api/auth/login` |
| `AUTH-002` | 현재 로그인 종료 | 로그인 | 세션 무효화 | 미인증, CSRF 실패 | `POST /api/auth/logout` |
| `AUTH-003` | 현재 로그인 회원 확인 | 로그인 | 화면 초기화에 필요한 회원 요약 반환 | 미인증, 회원 데이터 없음 | `GET /api/auth/me` |
| `AUTH-004` | CSRF 토큰 초기화 | 최종 CSRF 흐름 결정 | XSRF-TOKEN 쿠키 전달 후보 | 보안 구성 오류 | `GET /api/auth/csrf` 후보 |

`AUTH-003`을 현재 회원 조회의 단일 GET 계약으로 사용한다. 별도 프로필 상세 조회가 필요해질 때만 새로운 API를 추가한다.

### 구장·코트

| ID | 목적 | 선행 조건 | 성공 결과 | 대표 실패 조건 | API 후보 |
|---|---|---|---|---|---|
| `VEN-001` | 준비된 구장 목록 조회 | 목록 조건 유효 | 구장 목록 반환 | 잘못된 페이지·필터 | `GET /api/venues` |
| `VEN-002` | 구장 상세 조회 | venueId 존재 | 구장 정보 반환 | 구장 없음 | `GET /api/venues/{venueId}` |
| `VEN-003` | 구장별 코트 목록 조회 | venueId 존재 | 해당 구장의 코트 반환 | 구장 없음 | `GET /api/venues/{venueId}/courts` |

구장과 코트는 운영 시드 데이터다. 사용자 등록·수정 API와 실제 대관 가능 여부 조회는 만들지 않는다.

### 매치

| ID | 목적 | 선행 조건 | 성공 결과 | 대표 실패 조건 | API 후보 |
|---|---|---|---|---|---|
| `MAT-001` | 공개 매치 탐색·필터 | 목록 조건 유효 | 기본값으로 예정·모집 중·시작 전·남은 자리 있음 반환 | 잘못된 페이지·필터·enum | `GET /api/matches` |
| `MAT-002` | 매치 상세 조회 | matchId 존재 | 장소·시간·주최자·상태·정원 정보 반환 | 매치 없음 | `GET /api/matches/{matchId}` |
| `MAT-003` | 로그인 회원의 매치 개설 | courtId 존재, 시간·정원 유효 | `SCHEDULED`·`OPEN` Match 생성, 선택 시 주최자 참가 생성 | 미인증, 코트 없음, 시간·필드 오류 | `POST /api/matches` |
| `MAT-004` | 주최자의 시작 전 수정 | 본인 주최, 미취소, 시작 전, 변경 규칙 충족 | 허용 필드 갱신 | 권한 없음, 시작·취소, 잘못된 정원·시간 | `PATCH /api/matches/{matchId}` |
| `MAT-005` | 주최자의 모집 마감 | 본인 주최, `SCHEDULED`, 시작 전 | `OPEN → CLOSED` | 권한 없음, 시작·취소, 이미 마감 | `POST /api/matches/{matchId}/recruitment/close` |
| `MAT-006` | 주최자의 모집 재개 | 본인 주최, `SCHEDULED`, 시작 전, 남은 자리 있음 | `CLOSED → OPEN` | 권한 없음, 시작·취소, 자리 없음, 이미 OPEN | `POST /api/matches/{matchId}/recruitment/reopen` |
| `MAT-007` | 주최자의 매치 취소 | 본인 주최, `SCHEDULED`, **시작 전** | Match 취소와 모든 활성 참가 취소를 같은 트랜잭션에서 처리 | 권한 없음, 이미 시작·취소 | `POST /api/matches/{matchId}/cancel` |
| `MAT-008` | 내가 주최한 매치 조회 | 로그인 | 자신이 주최한 매치 목록 반환 | 미인증, 잘못된 목록 조건 | `GET /api/members/me/hosted-matches` |

### 참가

| ID | 목적 | 선행 조건 | 성공 결과 | 대표 실패 조건 | API 후보 |
|---|---|---|---|---|---|
| `PAR-001` | 최초 참가 또는 재참가 | `SCHEDULED`, `OPEN`, 시작 전, 남은 자리, 관계 없음 또는 `CANCELLED_BY_MEMBER` | 관계 생성 또는 기존 관계를 `CONFIRMED`로 전이 | 미인증, 매치 없음, 이미 참가, 마감·정원·시간·상태 충돌 | `POST /api/matches/{matchId}/participations` |
| `PAR-002` | 자신의 참가 취소 | 자신의 상태가 `CONFIRMED`, 시작 전 | `CONFIRMED → CANCELLED_BY_MEMBER` | 미인증, 관계 없음, 비활성 상태, 시작됨 | `DELETE /api/matches/{matchId}/participations/me` |
| `PAR-003` | 내가 참가한 매치 조회 | 로그인 | 참가 관계와 연결된 매치 목록 반환 | 미인증, 잘못된 목록 조건 | `GET /api/members/me/participating-matches` |
| `PAR-004` | 주최자의 참가자 목록 조회 | 로그인, 본인 주최 | 참가 관계와 회원 요약 반환 | 매치 없음, 권한 없음 | `GET /api/matches/{matchId}/participations` |

## 주요 상태와 전이

### Match

| 현재 상태 | 사건 | 다음 상태 | 조건 |
|---|---|---|---|
| 생성 전 | 매치 개설 | `SCHEDULED` | 정상 개설 |
| `SCHEDULED` | 주최자 취소 | `CANCELLED` | 현재 시각이 시작 전 |
| `CANCELLED` | 재활성화 | 전이 없음 | 항상 불가 |

시작·종료 여부는 별도 저장 상태가 아니라 현재 시각과 `startAt`, `endAt`으로 판단한다.

### 모집

| 현재 상태 | 사건 | 다음 상태 | 조건 |
|---|---|---|---|
| 생성 전 | 매치 개설 | `OPEN` | 정상 개설 |
| `OPEN` | 모집 마감 | `CLOSED` | `SCHEDULED`, 시작 전 |
| `CLOSED` | 모집 재개 | `OPEN` | `SCHEDULED`, 시작 전, 남은 자리 있음 |

### 참가

| 현재 상태 | 명령 | 다음 상태 | 활성 수 변화 |
|---|---|---|---:|
| 관계 없음 | 참가 | `CONFIRMED` | +1 |
| `CONFIRMED` | 회원 취소 | `CANCELLED_BY_MEMBER` | -1 |
| `CANCELLED_BY_MEMBER` | 재참가 | `CONFIRMED` | +1 |
| `CONFIRMED` | 매치 취소 | `CANCELLED_BY_MATCH` | -1 |
| `CANCELLED_BY_MATCH` | 재참가 | 전이 없음 | 0 |

매치 취소 시 이미 `CANCELLED_BY_MEMBER`인 관계는 그대로 두고 활성 관계만 `CANCELLED_BY_MATCH`로 바꾼다.

## 핵심 업무 규칙과 불변식

1. 한 회원은 한 매치에 하나의 참가 관계만 가진다.
2. `CONFIRMED`만 활성 참가자로 계산한다.
3. `confirmedCount <= maxParticipants`여야 한다.
4. `remainingSlots = maxParticipants - confirmedCount`는 음수가 될 수 없다.
5. 참가하는 주최자도 `CONFIRMED` 관계로 계산한다.
6. 참가·재참가 실패는 참가 상태와 정원에 영향을 주지 않는다.
7. 중복 참가로 두 관계가 생기거나 중복 취소로 자리가 두 번 복구되어서는 안 된다.
8. 매치 취소와 활성 참가 취소는 함께 성공하거나 함께 롤백한다.
9. Match는 Court만 참조하고 Venue를 중복 저장하지 않는다.
10. 권장 실력은 안내 정보다.
11. `endAt > startAt`이어야 한다.
12. 참가·참가 취소·매치 취소는 `현재 시각 >= startAt`이면 허용하지 않는다.
13. 정원을 늘려도 모집을 자동 재개하지 않는다.

현재 참가 수 저장 여부와 동시성 제어 방식은 이 불변식을 재현 테스트한 뒤 결정한다.

## 1차 MVP 완료 조건

- `MEM-001`~`MEM-002`, `AUTH-001`~`AUTH-003`, `VEN-001`~`VEN-003`, `MAT-001`~`MAT-008`, `PAR-001`~`PAR-004`의 정상 흐름이 구현된다.
- `AUTH-004`는 CSRF 흐름에 따라 구현하거나 불필요한 근거를 기록한다.
- 공개·로그인·주최자 경계가 일치하고 401·403을 구분한다.
- 참가·취소·재참가와 매치 취소가 허용된 상태 전이만 만든다.
- 중복 참가·중복 취소·마지막 자리 동시 요청에서도 관계 유일성과 정원 불변식이 유지된다.
- 매치 취소와 활성 참가 취소가 원자적으로 처리된다.
- 기본 탐색, 내 참가 매치, 내 주최 매치와 참가자 목록을 조회할 수 있다.
- 구장·코트 시드 데이터로 매치를 개설할 수 있고 Match가 Venue를 중복 참조하지 않는다.
- 검증·인증·권한·리소스 없음·상태 충돌 오류가 공통 형식으로 반환된다.
- 2차 MVP 기능이 1차 구현 범위에 섞이지 않는다.
- 구현과 테스트에서 확정된 사실을 관련 문서에 갱신한다.
